# Toolkit standalone source to cf Preview

Passed actual local build and live deployment on 2026-10-13. A fresh hosted
standalone repository generated by toolkit `0.1.464` was converted with
`scripts/prepare-preview-source.mjs`. Its custom `workspace.build`,
`workspace.check`, and `build:preview` commands were preserved. No production
source repository was changed.

The conversion removes only the known scaffold's Wrangler configuration and
dependency. It pins `cf@1.0.0-beta.14`,
`@cloudflare/vite-plugin@2.0.0-beta.sha-91c870c02`, `vite@8.3.4`, and
`@dtconcepts/timds@0.1.464`; npm generates the lockfile. The new assets-only
`cloudflare.config.ts` names the selected Worker, and `vite.config.mjs` uses
`dist` as `publicDir`. The pinned plugin's `createBuildApp`/`fallbackBuild`
path copies public files and removes its virtual entry when no root HTML
entrypoint exists. The generated config rejects root `index.html` and missing
`dist/index.html` to prevent accidental HTML transformation or empty deployment.

`npm run build:preview` ran the toolkit build and checks. Actual `cf build`
packaged all 41 output files with identical paths and SHA-256 digests, without
changing `dist`. Actual `cf deploy` and
`cf previews deploy review-source-conversion` then deployed the fixture.
Anonymous HTTP reads matched all 40 servable Preview files byte for byte;
`_headers` was verified through `X-Robots-Tag: noindex`. Main and immutable
Preview HTML also matched. The [sanitized receipt](./cf-preview-source.json)
records every digest, deployment identity, and cleanup result. This used direct
CLI deployment; the separate [Builds proof](./cf-preview-builds.md) covers
push-triggered production and branch execution.

The created Worker and named Preview were removed after verification. The
prepared tree remains at `/tmp/timds69-preview-source-proof` for host fixture
provisioning. Its source UUID is `6ffb48ea-862e-42de-9303-5edcbe8829d5`, system
ID is `timds/cf-preview-source-proof`, and provider URL is deliberately
`https://host-fixture.example`; set the actual host origin before provisioning.
Do not reuse the deleted deployment as a host-owned resource.

To prepare another fresh `.464` standalone tree, first review the default plan,
then explicitly select that tree for conversion, dependency installation,
toolkit checks, cf build, and digest comparison:

```sh
node scripts/prepare-preview-source.mjs \
  --source /absolute/disposable/source --worker timds-<source-uuid-without-hyphens>
node scripts/prepare-preview-source.mjs \
  --source /absolute/disposable/source --worker timds-<source-uuid-without-hyphens> --apply
```

The helper rejects existing Vite/Cloudflare configs, altered legacy bindings,
root HTML entrypoints, and other build frameworks. It does not convert arbitrary
imported systems. `--apply` performs no deployment or resource provisioning.

Cloudflare documents that `cf` invokes the build tool, skips package scripts,
and validates Build Output without requiring credentials. Therefore Builds
must retain `npm run build:preview` before either deploy command, and Preview
deployment must rebuild in Preview context. [CLI project documentation](https://developers.cloudflare.com/cf/projects/).
Static asset paths come from the Vite output/public directory, rather than an
`assets.directory` property in the new configuration. [Configuration documentation](https://developers.cloudflare.com/cf/projects/cloudflare-config/).
