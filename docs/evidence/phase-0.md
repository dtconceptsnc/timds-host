# TimDS open host #69 — cf toolchain spike

Date: October 12, 2026 (America/New_York).

## Toolchain decision

Pin `cf` to **1.0.0-beta.14** in package.json and commit package-lock.json. Use
`cloudflare.config.ts` and the Cloudflare Vite plugin generated by `cf init`.
The spike installed no Wrangler dependency; `npm ls wrangler` returned empty,
and `command -v wrangler` found nothing on PATH.

The installed global cf was already beta.14; it was not replaced. Node was
26.7.0, npm 11.19.0, Vite 8.3.4, Docker Desktop 28.3.2. Docker was initially stopped
and was started for local container development.

```sh
cf init /tmp/timds-host-cf-spike --package-manager npm --no-install
npm install --save-dev --save-exact cf@1.0.0-beta.14
cf d1 create --name timds-host-spike-69

cf containers push --tag timds-host-spike-69

cf deploy
cf dev
npm run typecheck
```

`cf deploy` builds images, pushes missing image digests, prepares the DO-managed
Container image, reconciles the SQLite DO export, deploys the Worker, and configures
the queue producer/consumer. No separate DO migration command is required for a
new class: declare it with `exports.durableObject({storage:'sqlite',container})`.

`cloudflare.config.ts`, `src/index.ts`, and Dockerfile in this spike contain the
exact working sample. The image runs Git 2.49.1 in an isolated Container. Bindings
cover D1, R2, Queue and Artifacts. The default fetch reaches its same-Worker DO
through `ctx.exports.RepositorySandbox.getByName('disposable')`.

version `416e52ae-f07b-476b-a16d-cd1fb0c4de8a`.

## Beta limitations and replacements

1. **`cf dev --local` is invalid.** beta.14 returns `--local is not supported by
   cf dev.` Use `cf dev`; Vite uses the local runtime and Docker containers.
2. **Artifacts is remote-only.** Invoking an Artifacts binding with its default
   local setting returns `Binding REPOS needs to be run remotely`. Configure
   `bindings.artifacts({namespace,dev:{remote:true}})`. A truly offline all-local
   host conformance suite requires an explicit test adapter for Artifacts; do not
   mislabel the native Artifacts binding as a local simulator.
3. **Same-Worker DO env binding bug.**
   `bindings.durableObject({worker:'timds-host-spike-69',exportName:'RepositorySandbox'})`
   emits `script_name`; cf deploy's container validator then incorrectly treats
   the class as belonging to another Worker, even when names match. The working
   replacement is to omit this redundant local env binding and use `ctx.exports`
   loopback namespace access. Keep the DO in `worker.exports`.
4. **Resource CLI names differ from the issue's shorthand.** Use plural
   `cf r2 buckets create`, `cf d1 create --name`, `cf queues create --queue-name`,
   `cf artifacts namespaces create --namespace`.
5. **Credentials:** cf's existing login had only Workers/Builds scopes. D1 and
   Artifacts create returned 401, R2 returned 403, and container push returned
   Forbidden. An existing unexpired broader user OAuth credential was supplied
   directly into each cf child process environment, without writing or printing
   its value. That successfully provisioned every resource and deployed the
   Container DO. Self-hosters must provide the documented product write scopes.
6. **No required Wrangler step was found for this spike.** Optional live logs
   remain a documented cf gap (`wrangler tail`; future cf live-log equivalent).
   Secrets can use `cf workers secrets bulk --file <secure-file>` or
   `cf deploy --secrets-file <secure-file>`; `cf workers secrets put` does not exist.
   `cf previews deploy [preview-name]` exists, but execution inside a Workers Builds
   trigger is a separate acceptance test and has not been claimed here.

The local probe used repository `probe-local`, the deployed probe `probe`. Each
initial repository token was revoked immediately, then a 60-second write token
was issued in the Worker, injected only by the trusted outbound HTTP proxy, and
revoked in `finally`. Container Git arguments, environment and files contain no
token. The D1 statement returned 1, R2 write/read returned the same commit, and
Queue producer send resolved. The queue handler acknowledges all spike messages.

Artifacts remote development's RPC error proxy did not preserve the documented
`.code` property in the duplicate-create case. A repeated create threw an Error
whose message was `ArtifactsError: repo already exists: probe`; the code-only
ALREADY_EXISTS catch missed it locally. Test adapter error normalization during
implementation instead of assuming local proxy Error metadata survives.

Phase 0 acceptance is satisfied for the container-backed DO deployment + Git
against Artifacts, without Wrangler on PATH or in dependencies. The issue's
literal `--local` and fully local Artifacts assumptions are unsupported by cf
beta.14; the documented replacements above are required.

### Cleanup complete

Deleted both disposable Artifacts repos and namespace, the R2 probe object and
bucket, D1 database, Container application, Queue consumer, Worker, Queue, and
both pushed registry image tags using cf. The Worker now returns HTTP 404.
The local Vite process was stopped; spike source, package lock, and local cache
remain in /tmp for reproducibility. Docker Desktop was left running because it
is required by the next host implementation steps.

Cleanup dependency order matters: delete the Queue consumer first, delete the
Worker second, then delete the Queue. Worker deletion rejects a live consumer,
and Queue deletion rejects a live producer binding. CLI resource IDs for delete
commands are positional; inspect command help, not only the API schema.

Resolved development dependencies: `@cloudflare/vite-plugin@2.0.0-beta.sha-91c870c02`,
`cf@1.0.0-beta.14`, `typescript@7.0.2`, `vite@8.3.4`.
